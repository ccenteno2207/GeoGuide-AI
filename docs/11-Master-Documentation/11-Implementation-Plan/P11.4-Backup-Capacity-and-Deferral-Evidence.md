## Read-only capacity assessment

Measured without stopping services, changing volumes or creating backups:

| Item | Bytes |
|---|---:|
| PostgreSQL/PostGIS volume | 113,406,353 |
| MinIO volume | 222,702 |
| Redis volume | 8,553 |
| TLS configuration volume | 71,216 |
| Required authoritative source | 113,700,271 |

Redis is classified `REPRODUCIBLE_OR_EPHEMERAL`: repository evidence describes Redis as optional cache with TTL, backend source contains no Redis client/cache usage, and the live instance contains one key. It is not included in the authoritative backup size.

Capacity scenarios, uncompressed worst-case and excluding compression assumptions:

| Scenario | Calculation | Bytes | With 30% margin |
|---|---|---:|---:|
| 7 daily | 113,700,271 × 7 | 795,901,897 | 1,034,672,466 |
| 7 daily + 4 weekly | 113,700,271 × 11 | 1,250,702,981 | 1,625,913,875 |

Recommended future off-host capacity: at least **2 GiB usable**, before growth planning. This is a capacity estimate, not an operational backup result. Compression is not treated as evidence; any compressed estimate requires measured backup artifacts later.

## Future design

- PostgreSQL/PostGIS: versioned logical dump plus checksum.
- MinIO: object copy/sync with integrity verification.
- Configuration: version-controlled non-secret configuration plus separately protected secret references.
- Redis: exclude while cache-only/reconstructible; reclassify if product state becomes non-reconstructible.
- Every run records exit code, checksum, available space, source/off-host target, retention and result.
- Restore uses an isolated target, validates schema/Flyway, POIs, PostGIS queries, MinIO objects and application recovery.
- RPO and RTO are measured only after off-host target exists.
